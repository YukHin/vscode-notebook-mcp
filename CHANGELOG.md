# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.6.1] - 2026-10-28

### Changed

- Publisher is now `yukhin`, so the extension id is `yukhin.vscode-notebook-mcp` (was `colmryan.vscode-notebook-mcp`, the upstream author's). VS Code treats it as a different extension: uninstall the old one. The access token is generated anew and Jupyter asks for kernel access again; clients using the bridge need no changes.
- Display name is now **Notebook MCP for Claude Code & Codex** (was "VS Code Notebook MCP"; Marketplace names shouldn't start with "VS Code"). The description says what the extension is for: letting agents other than GitHub Copilot work on open notebooks without save conflicts.
- Added an extension icon (`images/icon.png`, generated by `scripts/make-icon.py`).

## [0.6.0] - 2026-10-28

### Added

- `notebook_status` — whether the kernel matches the code on screen: code cells edited since they ran, cells not run in this kernel (outputs from disk, or before a restart), fresh cells that ran after one of those, running cells, unsaved changes. `notebook_list_cells` reports the same `state` per cell. Restarts are noticed whether they come from the tool or the editor.
- `notebook_run_cells` — run a range, everything from the first stale cell on (`mode: "stale"`), or all code cells, in order, stopping at the first error by default, with one summary and outputs only for the failing and last cells.
- `notebook_inspect_variables` — list kernel variables (type, shape/len, dtype, DataFrame columns) or describe named ones with a preview, through the Jupyter kernel API: no cell is added and the execution count doesn't change.
- Cells the agent changed or inserted show "Changed by agent" / "Inserted by agent" in their cell status bar until the user edits or runs them.
- Setting `notebook-mcp.confirmEdits` (off by default): before each insert, edit or delete, open a diff and ask to apply or reject; no answer within 2 minutes rejects.
- A stdio bridge (`~/.vscode-notebook-mcp/bridge.js`, kept up to date by the extension) that connects an MCP client to the VS Code window whose workspace contains the client's working directory, reads the token from the discovery file, and reconnects when the window restarts or its session expires. **Notebook MCP: Add to Claude Code** registers it (`claude mcp add --scope user notebook -- node …/bridge.js`); no token ends up in Claude Code's config.

### Changed

- **Copy Claude Code Command** now copies the bridge command instead of an HTTP command with the token.
- Idle MCP sessions are closed after 2 hours (and the oldest beyond 32); a request for an unknown session gets a 404 so clients start a new one.
- `notebook_restart_kernel` waits for the kernel to settle and no longer reports `dead` right after a successful restart.

## [0.5.0] - 2026-10-28

### Added

- `notebook_replace_in_cell` — replace one exact piece of text in a cell (unique match required unless `replace_all`), leaving the rest of the cell alone.
- `notebook_apply_edits` — several replace / whole-cell edits across cells, validated up front and applied in one workspace edit; if any edit fails, nothing changes.
- Stable cell ids. `notebook_list_cells` returns an `id` per cell (the nbformat id when the notebook has one, otherwise a session id), and every cell tool accepts `cell_id` as well as `index`.
- `timeout_seconds` on `notebook_run_cell` and `notebook_insert_cell`. A run that outlasts it returns `status: "running"` with the outputs so far instead of failing, and keeps running.
- `notebook_wait_cell` — wait for a running cell without starting it again.
- `notebook_interrupt_kernel` — stop running and queued cells without losing kernel state.
- `max_output_chars` and `max_images` on the tools that return outputs.

### Changed

- Each output is returned in one form, picked by preference (image, then stdout/stderr, Markdown, plain text, LaTeX, JSON, HTML), instead of every mime type it carries; a DataFrame no longer comes back as both HTML and text. Widget and JavaScript outputs are replaced by a short note.
- Text across all outputs of a call is fitted into `max_output_chars` (default 20,000), cutting long pieces in the middle and keeping the end. Images beyond `max_images` (default 4) or larger than 3.5 MB are replaced by a note.
- ANSI color codes are stripped from tracebacks and text.
- Code fences in Markdown results grow longer than any backtick run in the content, so cells containing ``` no longer break the formatting.
- The Plotly renderer is now an editor tab instead of a bottom-panel view. Rendering a Plotly figure no longer closes the panel (and with it the terminal).
- `index` is now optional on cell tools; pass `cell_id` or `index`.
- `notebook_select_kernel` now defaults to the user's setup. Without `kernel_id`/`python_path` it keeps a running kernel, or else attaches the workspace's selected Python interpreter (resolving conda-style environment folders to their executable), and only opens the picker when there is none. With an explicit choice it refuses to replace a running kernel unless `replace_running_kernel: true`, since switching discards the kernel's variables.
- `notebook_select_kernel` with `python_path` no longer leaves the workspace's Python interpreter changed. It still has to select the interpreter briefly so Jupyter creates a kernel for it, but switches the workspace back once the kernel is selected (reported as `workspaceInterpreterRestored`), so Pylance, terminals and debugging keep the user's choice.
- `notebook_list_cells`, `notebook_get_cell_output` and `notebook_interrupt_kernel` now see cells that are running, including runs started from the editor. Running cells were never detected before, because the Jupyter kernel gives a running cell no start time.
- `notebook_interrupt_kernel` uses Jupyter's interrupt command and returns within about 10 seconds even when the code ignores the interrupt (on Windows, `time.sleep` can't be interrupted until it returns).
- Plotly rendering works on repeated calls. VS Code doesn't run hidden webviews, so the renderer tab is shown (without taking focus) while figures render, and the previous editor is back in front before the tool replies — once per call, however many figures it has.
- Removed `extensionDependencies` on the Jupyter extension, which forced Jupyter to activate in every window at startup. Jupyter is still required and is activated when a tool first needs it.

### Internal

- Integration tests resolve venv interpreters with `Scripts\python.exe` on Windows.

## [0.4.0] - 2026-10-28

### Security

- The MCP endpoint now requires a bearer token. It is generated on first run, kept in VS Code's SecretStorage, and can be copied as a ready-to-run `claude mcp add` command (`Notebook MCP: Copy Claude Code Command`) or rotated (`Notebook MCP: Regenerate Access Token`).
- Requests are refused unless the `Host` header is `127.0.0.1:<port>` or `localhost:<port>` (DNS-rebinding protection) and refused if they carry an `Origin` header. CORS headers are no longer sent. Previously any web page open in a browser could drive the server and execute code in the kernel.

### Added

- `notebook_save` — write the editor's in-memory notebook to its `.ipynb`.
- MCP `instructions` telling agents to use these tools, not file tools, for notebooks open in VS Code, and to save when done.
- Tool annotations (`readOnlyHint` / `destructiveHint` / `openWorldHint`) so clients can tell reads from edits and code execution.
- A discovery file per window at `~/.vscode-notebook-mcp/<pid>.json` with the URL, port, token and workspace folders; stale files from crashed windows are removed.

### Fixed

- Re-running a cell that had run before could return the previous run's outputs, because completion was detected by `executionSummary.success` alone. The tools now wait for a summary that differs from the one before the run.
- `notebook_run_cell` tracked the cell by index while waiting, so inserting or deleting cells meanwhile could return another cell's outputs or fail out of range. Cells are now tracked by object, and a cell deleted mid-run is reported as such.
- `notebook_select_kernel` with `python_path` computed the wrong controller id on Windows. Windows paths are now normalized the way the Jupyter extension does it (hash of the Uri path, fsPath in the id).
- Waiting for execution listens to notebook change events instead of polling every 100 ms.
- The server reports the real extension version instead of `0.1.0`.

## [0.3.0] - 2026-05-31

### Added

- `notebook_restart_kernel` — restart a notebook's kernel, clearing all in-memory state (variables, imports) while leaving cell outputs intact. The underlying Jupyter command returns before the kernel has actually restarted, so the tool watches the kernel's status and waits for it to settle back to idle (bounded by a start-grace and total timeout) before returning, so a follow-up execution doesn't race a half-restarted session.

### Internal

- Integration coverage for `notebook_restart_kernel` (happy-path wiring + the no-kernel-connected guard). The headless `@vscode/test-electron` host does not honor the Jupyter restart command against the live kernel, so true state-wipe is verified by the manual SOP (CLAUDE.md row 20), confirmed end-to-end in the dev host: the execution count resets and a reference to a pre-restart variable raises `NameError`.

## [0.2.0] - 2026-05-31

### Added

- `notebook_select_kernel` accepts a `python_path` (an interpreter path, e.g. a venv's `bin/python`): attach a kernel without knowing a controller id or having pre-selected the interpreter in VS Code. The tool registers the interpreter with the Python extension, computes the controller id for you, and retries selection until the controller is live.

### Internal

- Integration test suite (`@vscode/test-electron` + Mocha) driving the MCP tools through an in-memory transport; `npm test` provisions uv-managed kernel venvs.
- Removed application-scoped keys from the test workspace settings that triggered a VS Code "can only be written into User settings" warning.
- Docs: manual end-to-end tool-exercise SOP, and a rationale for each carried dependency.

## [0.1.0] - 2026-05-10

Initial release.

### Added

- Embedded HTTP MCP server inside the VS Code extension host on `127.0.0.1:49777` (configurable via `notebook-mcp.port`; auto-increments up to +99 if the port is busy). Speaks MCP over `StreamableHTTPServerTransport`; also exposes `GET /health`.
- A fresh `McpServer` is created per session so multiple MCP clients can connect concurrently without colliding on a shared transport.
- 13 MCP tools covering the full notebook-editing loop:
  - **Discovery** — `notebook_list_open`, `notebook_open`, `notebook_list_cells`, `notebook_get_cell_content`, `notebook_get_cell_output`.
  - **Cell manipulation** — `notebook_insert_cell`, `notebook_edit_cell`, `notebook_delete_cell`.
  - **Execution** — `notebook_run_cell`, `notebook_clear_cell_output`, `notebook_clear_all_outputs`.
  - **Kernel** — `notebook_get_kernel_info`, `notebook_select_kernel`.
- All tools accept an optional `notebook_uri` (defaults to the active notebook editor) and a `response_format` of `"markdown"` or `"json"`.
- Edits flow through `vscode.NotebookEdit` + `vscode.WorkspaceEdit` so they participate in undo/redo and share state with the editor.
- Inserted cells are tagged with a `metadata.id`, letting the executor track them across concurrent edits that shift cell indices.
- Plotly outputs (`application/vnd.plotly.v1+json`) are rendered to PNG via a hidden `WebviewView` and returned as MCP image content blocks alongside the markdown summary.
- Status bar item showing server state, using the VS Code notebook codicon.
- Commands: `Notebook MCP: Restart Server`, `Notebook MCP: Show Server Info`.
- Packaging support via `@vscode/vsce`: `.vscodeignore` keeps the VSIX small (only `dist/`, `package.json`, `README.md`, and `LICENSE` ship); `repository` field set in `package.json`.
